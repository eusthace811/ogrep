# Evidence inventory

The final results are explained in [BENCHMARKS.md](../BENCHMARKS.md). JSON files retain samples, complete-output hashes, versions, executable hashes, corpus revisions, and query definitions. Logs record command progress; the JSON is the authoritative timing record.

## Final performance evidence

- `final-cpython-local.json`, `final-cpython-server.json`: 12 queries, 21 rounds per mode.
- `final-rust-local.json`, `final-rust-server.json`: 12 queries, 21 rounds per mode.
- `final-upstream-rust-server.json`: 102 upstream-derived queries, 11 rounds.
- `final-summary.json`: per-query median speedup, paired-round bootstrap intervals, and aggregates. Generated by `scripts/summarize-evaluation.py`.
- `upstream-query-results.md`: every query in the independent workload, including slower cases.
- `queries-*.json`: exact workload definitions. The upstream workload uses 91 literal strings and 11 regexes from the original checked-in benchmark list.

The evaluator gained an explicit cross-engine exit assertion after the first final runs started. The summary script independently checks that all stored validation row counts, full-output hashes, and exit codes agree across engines; all five final evaluations passed that check. During timing each run was already required to reproduce its own engine's validated output and exit. This adjustment did not change the measured binaries or samples.

## Earlier experiments

`baseline-*` compares upstream with the renamed unmodified fork. `lazy-*` evaluates cardinality/probe execution. `boolean-*` isolates nested Boolean preservation. `position-*` combines planner changes and masks. These are exploratory, with fewer rounds and some development/build activity overlapping parts of the overall experimentation period; prefer final runs for end-to-end claims.

`position-profile-cpython.json` is an in-process executor microprofile on the same new plan for both executors, not a recreation of old regex parsing. `sparse-*.json` compares deterministic samples; the candidate and posting counts motivated rejecting that prototype for release. Corresponding source examples and property-test logs are retained.

Historical failures are preserved rather than relabeled:

- `lazy-tests.log`: six inherited Git-ignore fixture failures in the earlier restricted environment, which exposed a synthetic `/tmp/.git` to temporary directories. The full suite passes in the current unrestricted environment without changing those assertions.
- `lazy-workspace-tests.log`: a restored-mtime recovery fixture assumed ctime advanced within the same filesystem tick. Commit `92406b2` waits for that fixture precondition and retains the recovery assertions. The final workspace run passes.
- `pi-tests.log`: mistaken direct invocation of `test_pi.mjs` without the generated extension arguments required by that driver. It is not a valid integration-test invocation. The Python test harness provides the actual extension and passes the roundtrip in `final-agent-tests.log`.

Other build/test logs retain the progression of experiments. Earlier version strings reflect the pre-release rename stage; the final measured executable is 0.1.0.
